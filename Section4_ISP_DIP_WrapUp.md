# Section 4 — ISP + DIP Wrap-up

If the bank needs a new `MongoAccountRepository`, I would create `MongoAccountRepository.py` implementing the existing `AccountRepository` interface and touch only `Main.py` to swap the repository implementation. `Bank.py` would not need to change because it already depends on the `AccountRepository` abstraction rather than a concrete storage class. Similarly, a new notification service can be added as another implementation of `NotificationService` without changing the bank's internal logic. In the original Lab 1 design, database, notification, statement, and account responsibilities were mixed into `BankAccount`, so a new storage or notification requirement could have forced changes to that single large class. The four-lab design keeps responsibilities separated and lets new capabilities be added with much less modification to existing code.
